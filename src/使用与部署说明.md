# ICC全球大考报名系统 · 使用与部署说明

## 一、现在这套是什么

已经不是演示原型了，是**能真跑的系统**：一台机器当服务器，学生用浏览器（电脑或手机）访问，数据统一存在服务器上的 `data/` 目录里，教务在后台能看到全部提交和纠错工单。

- 学生名单**不再下发到浏览器**，姓名和出生日期都送到服务器比对，学生端拿不到全班名单
- 提交、纠错、教务更正、纸质签署状态，全部实时写入服务器
- 数据按**考试季分文件存放**，一季一个文件，互不干扰

## 二、日常怎么用

1. 双击 `启动服务.bat`（或命令行 `node server.js`）
2. 服务器上本机访问：`http://localhost:8080`
3. 学生访问：查服务器的局域网 IP（`ipconfig` 里的 IPv4 地址），学生浏览器打开 `http://192.168.x.x:8080`
   - 手机连校园无线即可访问，前提是和服务器在同一网段
4. 教务后台：页面底部「教务后台」按钮，输入口令登录（默认 `exam2026`，**务必先改**）

**改口令**：数据文件已加密，不能再直接编辑 `data/admin.json`。在 `src/` 下执行：

```bash
node tools/set-password.js 你的新口令
```

口令至少 8 位，改完重启服务确认。若密钥来自环境变量 `EXAM_DATA_KEY`，执行时也要带上同一个变量。

服务已在云端运行时，可用教务令牌调用 `POST /api/admin/passwd`（`{"newPass":"新口令"}`）远程修改。

## 三、每个考试季怎么开

教务后台顶部有「考试季管理」：

1. **新建并切换**：填编号（如 `2026-winter`）、名称、开放与截止时间、适用班级（英文逗号分隔），是否复制上一季名单
2. **导入名单**（两种方式任选）
   - **推荐：Excel 导入工具**（见下方「用 Excel 导入名单」），自动识别表头、规范日期、脱敏预览后再写入
   - 后台文本框粘贴，每行一条，格式为 `学号,班级,中文名,姓名大写,性别,出生日期`
     例：`S001,IG1,张思远,ZHANG SIYUAN,男,2009-03-12`
3. **归档当前季并导出三件套**：报考汇总 CSV、待复核名单 CSV、未提交名单 CSV，文件名自带季编号
4. 已有提交记录的考试季**不允许整体替换名单**，如需换名单请新建一季

数据文件：`data/seasons/<编号>.json`，一个季一个文件（**已加密**，备份时须连同 `data/.key` 一起备份）。

### 用 Excel 导入名单

```bash
# 1. 先启动服务：node server.js
# 2. 预览（默认只预览，不写入；打印字段映射、统计和脱敏结果）
python tools/import-roster.py -f 名单.xlsx

# 3. 确认无误后导入（口令用环境变量传，避免留在命令行历史）
EXAM_ADMIN_PASS='教务口令' python tools/import-roster.py -f 名单.xlsx --commit

# 导入远程/线上实例：完整地址（含分享参数）直接作为 --url
EXAM_ADMIN_PASS='教务口令' python tools/import-roster.py -f 名单.xlsx \
    --url "https://<域名>/?sharecode=<分享码>" --commit --yes
```

- 支持 `.xlsx` / `.csv`，零第三方依赖；自动在前 10 行里找表头，识别「学号 / 班级 / 中文姓名 / 姓名大写 / 性别 / 出生日期」，支持中英文别名、列乱序、多余列
- 出生日期兼容 `2009-03-12`、`2009/3/12`、`2009年3月12日`、8 位数字、Excel 日期序列号；性别兼容 男/女/M/F
- 表头没认出来时用 `--map 字段=表头名` 指定，如 `--map dob=出生年月`；多工作表用 `--sheet 工作表名`
- 会检查学号重复、**班级+姓名重复**（同班同名会导致身份匹配失败，拒绝导入）和日期异常
- 导入同时自动同步学生端的班级下拉；已有提交记录的考试季，服务端会拒绝整体替换名单
- **绝不把 Excel 放进 `public/`，也绝不提交到 git**。名单只经服务端接口写入加密数据文件，前端源码里不会留下任何真实学生信息
- 随交付包提供 `学生名单模板.xlsx`（含「名单」「填写说明」两个工作表），可直接照抄列名；**导入后请删除本地表格**
- 已有提交记录时服务端会拒绝整体替换名单，请先在教务后台「新建考试季」，再对新季导入
- **学号是第二验证因子的依据**：开启双因子后学生验证须填学号后四位，数字不足 4 位自动左补零（`S001 → 0001`）。未提供学号列时工具会生成 `S001、S002…`，请补全真实学号、告知学生或先关闭双因子；报考期间不要改动学号

## 四、上云的三种方式（按推荐顺序）

### 方式 A：校内一台常开的电脑（推荐先跑这个）

零成本、数据不出校、不需要任何审批。找一台机房或教务办公室常开的电脑，双击启动即可。
注意：这台电脑必须保持开机、不休眠，学生才能访问。

### 方式 B：腾讯云轻量应用服务器

- 数据存在云硬盘上，重启不丢，比容器方案省心
- 费用：新人活动一般几十元一年起步，按量也有低价档
- 步骤：买轻量服务器（选 Ubuntu）→ 装 Node 22 → 上传 `server.js` 和 `public/` → `node server.js` 后台运行（用 `systemd` 或 `pm2` 守护）
- 访问可用 IP 直接访问；要用域名需备案

### 方式 C：腾讯云开发 CloudBase

弹性最好、不用运维服务器，但**注意一件事**：云托管容器的本地磁盘在重启后会清空，必须挂载文件存储（CFS）或改用云数据库。

迁移成本很低，因为整套数据就是一个 JSON 对象，只需要把 `server.js` 里两个函数换掉：

```js
readJSON(p, def)   →   从云数据库读一个文档
writeJSON(p, o)    →   写回该文档
```

其余业务代码一行不用动。建议的路径是：

- 静态页面（`public/`）→ 静态网站托管
- `server.js` 的接口 → 云函数
- `data/seasons/<季>.json` → 云数据库集合 `seasons`，一季一条文档

## 五、上云前必须确认的两件事

1. **腾讯云账号归属**：用学校主体还是个人实名？个人账号后续交接麻烦，建议用学校或教务组公用账号。
2. **学生信息上云的合规**：姓名、性别、出生日期属于个人信息。上公有云前，务必确认学校允许。若不允许，就走方式 A，功能完全一样。

## 六、安全提醒

- 默认口令 `exam2026` 必须改，命令见第二节；改后其他已登录会话立即失效
- **`data/.key` 是解密学生数据的唯一钥匙**：必须单独备份、绝不上传仓库、绝不放进 `public/`。密钥丢失 = 数据永久无法恢复
- 正式对外使用请配 HTTPS（CloudBase 自带，轻量服务器可用 Let's Encrypt 免费证书）
- 每季结束后把 `data/seasons/` 与 `data/.key` 一起复制归档；另用后台「数据备份与恢复」导出一份口令加密备份单独保管
- 正式启用前按第十一节完成安全与合规设置（告知文本、必须先同意、第二验证因子）
- 验证失败按「出口 IP + 班级 + 学生 ID」计数，连续 3 次锁 15 分钟、当次即提示锁定并计入后台告警；教务登录连续 5 次失败锁 10 分钟
- **备份口令不落盘、不写日志，忘记即无法恢复**；请按学校规定单独保管，不要与备份文件放一起

## 七、数据安全设计（重要）

**名单放在哪里、怎么被发现**是这套系统的关键。六层防护：

1. **名单只存服务端**：`GET /api/boot` 只返回班级、科目、须知，**不含任何学生姓名或出生日期**。生产前端连演示名单都不预置，浏览器内存里只有验证通过后的本人档案（会话级缓存）。
2. **服务端比对**：姓名（中文或大写拼音，忽略大小写/空格/连字符）与出生日期都送到服务端比对，学生端拿不到全班名单，F12 / 查看网页源码都翻不到。
3. **验证失败绝不返回凭据**：出生日期不对时只返回打码线索（如「张\*」+ 班级 + 性别），不返回真实出生日期、完整档案或已提交记录；纠错工单文本也不写学籍真实出生日期。这堵住了「随便填错日期就能拿到别人档案并冒充提交」的绕过路径。
4. **落盘加密**：`data/` 下所有 JSON 用 AES-256-GCM 加密，密文带认证标签防篡改。密钥默认自动生成在 `data/.key`，云部署可用环境变量 `EXAM_DATA_KEY` 注入。旧版明文数据在首次启动时自动加密迁移，业务数据不丢。写入采用「临时文件 + 原子 rename」，不会留下半截密文。
5. **第二因子与个人信息告知**：后台可按考试季开启 `sid4`（出生日期 + 学号后四位，学号数字不足 4 位自动左补零）；告知未同意时 `/api/verify` 直接返回 `privacy`，连姓名是否存在都不探测，同意 / 拒绝均留痕。
6. **加密备份与异常兜底**：整季可导出 `EXAMBAK1:` 口令加密备份（见第十节）；单个请求异常返回明确错误，不会让服务进程退出。

其他加固：教务令牌绑定登录 IP、8 小时过期；学生端只能把「教务已更正」的工单复核为已确认，不能伪造工单状态；静态资源禁止路径穿越与隐藏文件访问；响应统一带 `no-store` / `nosniff` / 无 referrer / CSP 头，普通浏览器另有 `X-Frame-Options: DENY` 与 `frame-ancestors 'none'` 防点击劫持（钉钉客户端例外，见第十三节）。

**仍需注意**：双因子不属于强身份认证，弱凭据与合规约束见第九节第 5、7 条及第五节。

## 八、输入时间与终端设备记录

学生每次**验证、提交、重新提交、越权写入被拒**，以及教务保存数据，都会写入当前考试季的 `logs` 时间线：

| 字段 | 来源 | 说明 |
|---|---|---|
| `at` | **服务端时钟** | UTC ISO 时间戳，不信任客户端传的时间 |
| `sid` / `action` | 服务端 | 学号与动作类型 |
| `ip` | 服务端 | 默认取 TCP 对端地址；只在设置 `TRUST_PROXY=1` 时才读 `X-Forwarded-For` |
| `fwd` | 服务端 | 参考来源 IP：转发头首段，导出 CSV 中列为「参考来源IP(可伪造)」，**不参与锁定/鉴权判定** |
| `device` | 服务端解析 UA | 设备类型 / 品牌 / 型号 / 操作系统 / 浏览器 / 内嵌 App（微信、企业微信、QQ浏览器、钉钉工作台及版本）/ UA 原文 |
| `clientHint` | 客户端上报 | 屏幕分辨率、DPR、`userAgentData.model` 等，**可伪造，仅作参考** |

- 学生本人的提交记录里同时保存 `inputAt`（服务端时间）、`lastDevice`、`devices`（最多 10 台），回执页会显示提交时间与设备。
- 教务后台「输入时间与终端设备记录」面板显示最近 50 条，可一键导出 `…-输入时间与设备.csv`（含全部字段）。
- 每季最多保留 **5000 条**，超出后丢弃最早记录；需要长期留档请每季导出 CSV 归档。
- 相同内容的重复同步（心跳）不会刷新提交时间，也不会增加重填次数。

**共享出口 IP 的处理**：校园 NAT 或云端反向代理下，所有访客的 TCP 对端可能恒为网关地址（线上实测为 `127.0.0.1`）。因此失败锁定按「出口 IP + 班级 + 学生 ID」计数，而非只按 IP——否则一人填错 3 次会锁住同一出口下的所有人；也不按输入姓名计，否则同一学生交替用中文名 / 大写拼音即可绕过次数限制。锁定期结束后失败计数会清零重新计起，第 3 次失败当次就会返回锁定信息。教务登录限流仍按 IP，共用出口时存在被恶意刷错口令造成短暂拒绝服务的可能，强口令下不构成爆破风险。

**设备型号能精确到什么程度（重要限制）**：

| 终端 | 能识别到 |
|---|---|
| Android 手机/平板 | 通常能拿到具体机型串，如「小米 Mi 10」「华为 HUAWEI P40 Pro」「三星 SM-S918B」 |
| iPhone / iPad | **只能到设备系列 + iOS 版本**（如「Apple / iPhone / iOS 17.1」）——Apple 的 UA 不含具体机型 |
| Windows / macOS | 只能到操作系统 + 浏览器，**拿不到 PC 型号** |
| 全部 | UA 可被伪造，设备信息是辅助证据，不能当作强身份凭据；校园 NAT 下多名学生可能共用一个出口 IP |

系统已采集浏览器 UA-CH 高熵值（`navigator.userAgentData.getHighEntropyValues` 的机型、平台版本、架构、位数、完整版本列表），写入 `clientHint` 并在导出 CSV 中单列且标注「可伪造」，可作为型号补充线索；但它同样是客户端上报，不能作为强凭据。若业务上必须精确到 iPhone 具体型号或 PC 资产编号，仍需学校 MDM / 设备登记，或让学生用校园账号登录后关联设备台账。

## 九、云端实例与已知限制

在线实例运行**完整 Node 后端**，仅用于验证全流程；访问地址与凭据见《上线测试指引》。生产前端不预置任何学生名单，连接失败时只显示「报名服务暂不可用」，不会退回虚构数据或离线填写；完整离线流程演示见 GitHub Pages 演示页。当前版本与 `src/` / `handover/` 源码一致，本地 77 项回归及线上各轮复测全部通过（明细见该指引第七节）。

当前仍然存在的限制，不粉饰：

1. **云端沙箱不保证数据持久**：容器重启/重新部署可能清空本地文件与自动生成的密钥。线上实例只用于验证，不能作为正式报考的唯一数据存储。
2. **单实例写**：单进程内「读—改—写」是连续的、不会交错；但若跑多个进程/实例指向同一份数据，会互相覆盖。大规模使用应把存储层换成数据库（只需替换 `lib/secure-store.js` 的 `readJSON`/`writeJSON`）。
3. **密钥与数据同机**：加密防「数据文件被单独拷走」，不防「整台机器被拿下」。
4. **教务后台会拿到全量名单**：这是授权功能，但令牌一旦泄露即为全量泄露；令牌已绑定登录 IP、8 小时过期。
5. **合规**：设备型号、IP、时间戳同样属于个人信息，采集前需按学校规定告知学生并留存依据。
6. **真实名单需自行导入**：本仓库不含任何真实学生数据。拿到表格后按第三节流程操作，名单只写入服务端加密文件；导入后删除本地表格。
7. **双因子不是强认证**：学号后四位与出生日期都可能被同学知晓；高风险场景仍需线下核发一次性验证码或接入校园统一身份认证。
8. **重新部署不保证数据持久**：本次实测保留了 `data/` 与后台口令（分享链接不变），但容器重建仍可能清空，正式使用以本地加密备份为准。


## 十、加密备份与恢复（重要）

后台「数据备份与恢复」面板：

1. **导出**：输入至少 8 位的备份口令 → 点「导出加密备份」→ 下载 `…-<考试季>.bak` 文本文件。内容是 `EXAMBAK1:` 开头的 AES-256-GCM 密文，密钥由该口令经 scrypt 派生，**不依赖 `data/.key`**。
2. **恢复**：选择备份文件、填同一口令、按需勾选「覆盖同名考试季」→ 点「恢复」。服务端依次校验格式 / 版本 / 口令与 GCM 认证标签 / SHA-256 校验和 / 考试季结构，任一不通过都不写盘。
3. **适用场景**：云端容器重建、换服务器、密钥丢失、误删考试季。换新机器后只要有备份文件 + 备份口令即可完整还原名单、提交记录、工单与时间线，并立即用新密钥重新加密落盘。

备份口令不写入任何数据文件、不进日志、不进仓库。**忘记口令 = 备份不可恢复**；备份文件本身虽是密文，仍含学生个人信息，按学校规定离线保管、不要发微信群或提交 git。

## 十一、安全与合规设置（每季确认一次）

后台「安全与合规设置」面板可修改当前考试季并立即保存：

| 项 | 说明 |
|---|---|
| 启用第二验证因子 | 勾选后学生须同时填对出生日期与学号后四位，输入框自动出现在第 1 步；学号数字不足 4 位自动左补零，名单里的学号即该因子的依据 |
| 必须先同意个人信息处理告知 | 建议保持勾选；未同意时服务端直接拒绝验证，不做姓名探测 |
| 个人信息处理告知文本 | 按学校 / 大考主办方规定修改，最长 1500 字；同意与拒绝动作均写入时间线 |

修改配置会留痕（`admin_config`），可在「输入时间与终端设备记录」面板查到。

## 十二、回归验证

```bash
cd src
PORT=8093 node server.js          # 建议用空 data/ 目录另起端口，脚本会改口令、窗口并写入测试记录
python tools/verify.py            # 77 项断言；VERIFY_URL 可指定其他地址
```

## 十三、钉钉工作台 H5 微应用

把服务地址配成企业内部 H5 微应用的「应用首页地址」和「PC 端首页地址」，创建并发布版本后，师生可在钉钉工作台直接打开同一套后端，不需要另做前端或复制数据。

- **PC 端用 iframe 嵌入**：`X-Frame-Options: DENY` / `frame-ancestors 'none'` 会让 PC 工作台出现空白页。服务端按请求 UA 判断，仅钉钉客户端（`DingTalk`、`AliApp(DingTalk/…)`、`com.laiwang.DingTalk`）省略 DENY 并把 CSP 改为 `frame-ancestors *`；普通浏览器、微信等仍禁止嵌套，保留点击劫持防护。
- **兼容开关**：某些定制客户端 UA 无法识别时，可设置 `EXAM_FRAME_ANY=1` 放宽所有来源；这会失去点击劫持防护，只允许在受控内网使用。
- **WorkBuddy 云端网关**会剥离 `X-Frame-Options` 并在 `frame-ancestors` 追加 `*`，不受本代码控制；因此公网云端实例天然允许任意站点 iframe 嵌套，**不可作为正式报考环境**。自建服务 / 校内服务器不受影响。
- 钉钉内置浏览器在设备时间线里记为「钉钉 x.y.z」，与设备型号同时留痕，教务后台可按渠道区分。
- **可见范围按「仅教务小范围」设置**，不要设为全员可见；测试环境尤其不要向全体师生开放。
- 应用首页 URL 若带 `?sharecode=` 等查询参数，钉钉控制台会原样保留；不要在工作台链接里追加后台口令或学生名单。
