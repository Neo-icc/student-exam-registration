# ICC全球大考报名系统

ICC全球大考报名系统：学生核对本人学籍档案 → 勾选报考科目与单元 → 线上确认；教务后台处理纠错工单、导出报考汇总。

## 在线演示（GitHub Pages）

访问仓库对应的 Pages 地址即可打开**公开演示页**。

> 演示页运行在「离线演示模式」：完整流程都可以操作（身份验证、信息核对、纠错工单、科目选择、签名提交、教务后台、三件套导出），但**所有数据只保存在访客自己的浏览器 localStorage 中，不会上传、不会被教务收到**。页面内 14 名学生均为虚构示例数据。
>
> 体验账号：班级 `IG1` / 姓名 `张思远` / 出生日期 `2009-03-12`。
>
> 底部「教务后台（本机演示）」无需口令，可直接查看演示数据。

## 正式使用：跑完整服务端

GitHub Pages 是静态托管，无法运行 Node 服务，因此**不能用于真实收集学生提交**。正式报考需要一台能跑 Node 的机器（校内常开电脑 / 云服务器均可）。

```bash
cd src
node server.js
# 本机：http://localhost:8080
# 局域网：http://<服务器IP>:8080
```

Windows 用户也可直接双击 `src/启动服务.bat`。

- 首次运行自动生成 `src/data/`（考试季、虚构示例名单、后台口令 `exam2026`）以及**数据加密密钥** `src/data/.key`
- **正式使用前务必改口令**：`node tools/set-password.js <新口令>`（数据已加密，不能再直接编辑 `admin.json`）
- **`src/data/.key` 必须单独备份、绝不上传仓库**。密钥丢失 = 学生数据永久无法解密
- 教务后台在页面底部，可管理考试季、导入名单、处理纠错、导出 CSV
- 每个考试季单独一个 `src/data/seasons/<编号>.json`（密文），归档时连同密钥一起备份

数据文件含学生个人信息与后台口令，**已通过 `.gitignore` 排除，不会上传到本仓库**。

## 导入真实学生名单（Excel）

真实名单只能通过服务端接口写入加密数据文件，**绝不放进 `public/`、绝不提交 git**：

```bash
cd src
node server.js                                    # 先启动服务
python tools/import-roster.py -f 名单.xlsx          # 默认 dry-run：只打印字段映射与脱敏预览
EXAM_ADMIN_PASS='教务口令' python tools/import-roster.py -f 名单.xlsx --commit
```

支持 `.xlsx` / `.csv`，零第三方依赖；自动识别表头（中英文别名、乱序、多余列），规范日期与性别，检查同班同名等重复，导入后自动同步班级下拉。详见 `src/使用与部署说明.md`。

导入远程实例时，把完整地址（含分享参数）作为 `--url` 传入，例如 `--url "https://<域名>/?sharecode=<分享码>"`；工具会把分享参数正确拼到每个接口请求上。

> **学号是第二验证因子的依据**：考试季开启双因子后，学生验证需填学号后四位，学号数字不足 4 位自动左补零（`S001 → 0001`）。若 Excel 未提供学号列，导入工具会按行序生成 `S001、S002…`，请补全真实学号、另行告知学生，或在后台关闭双因子后再导入；报考期间不要改动学号。模板「填写说明」表已写明该规则。

| 路径 | 说明 |
|---|---|

| `src/public/index.html` | 正式前端单页；**不预置任何学生名单**，仅会话级缓存本人档案；服务器不可达时只读提示，不提供离线填写 |
| `src/server.js` | 零依赖 Node 服务端，HTTP 接口 + 加密 JSON 存储 |

| `src/lib/device-log.js` | User-Agent 设备解析、输入时间线写入、客户端上报项脱敏 |
| `src/lib/backup.js` | 整季加密备份 / 恢复（口令经 scrypt 派生，不依赖 `data/.key`） |
| `src/tools/import-roster.py` | Excel/CSV 名单识别与导入（默认只读预览） |
| `src/tools/set-password.js` | 修改加密后的教务后台口令 |
| `src/tools/verify.py` | 全量回归验证（77 项接口 / 加密 / 攻击面 / 钉钉工作台内嵌断言，零第三方依赖） |
| `src/使用与部署说明.md` | 日常使用、考试季管理、备份恢复、三种上云方式、数据安全设计 |
| `src/启动服务.bat` | Windows 一键启动 |

## 服务端接口概要

| 接口 | 用途 |
|---|---|
| `GET /api/boot` | 学生端配置（**不含学生名单**），下发双因子与个人信息告知配置 |
| `POST /api/verify` | 姓名 + 出生日期（可选 + 学号后四位）服务端比对；须先同意告知 |
| `POST /api/push` | 学生写回本人记录 / 工单 |
| `POST /api/admin/login`、`GET /api/admin/state`、`POST /api/admin/save` | 教务登录与数据读写 |
| `POST /api/admin/passwd` | 修改教务口令，其余会话令牌立即失效 |
| `POST /api/admin/backup`、`POST /api/admin/restore` | 整季加密备份导出 / 恢复 |
| `POST /api/admin/season` | 考试季切换、新建、名单导入、归档、安全与合规配置 |

## 数据安全设计

真实学生名单**不可能**放在 GitHub Pages 这类静态页面上——静态文件会被浏览器完整下载，F12 就能看光。因此名单只存在于服务端，并采取四层防护：

1. **不下发名单**：`/api/boot` 只返回班级、科目、须知；生产前端不预置名单，浏览器里只有验证通过后的本人档案。
2. **服务端比对**：姓名（中文 / 大写拼音，忽略大小写与空格）和出生日期都在服务端比对。
3. **验证失败绝不返回凭据**：修复了原交接包中的绕过路径——旧版在出生日期填错时仍返回 `code:"ticket"` 并附真实出生日期、完整档案和已提交记录，前端还把它当作验证成功并清零失败计数，等于「知道班级+姓名就能冒充」。现在失败只返回打码线索，纠错工单文本也不含真实出生日期。
4. **落盘加密**：`data/` 下所有 JSON 用 AES-256-GCM 加密（带认证标签防篡改），密钥为 `data/.key` 或环境变量 `EXAM_DATA_KEY`；旧版明文数据首次启动自动迁移。

其余加固：教务令牌绑定登录 IP、8 小时过期、连续 5 次失败锁 10 分钟、改口令后其余会话立即失效；学生端只能把「教务已更正」的工单复核为已确认，不能伪造工单状态；静态资源禁止路径穿越与隐藏文件；响应统一带 `no-store` / `nosniff` / 无 referrer / CSP，普通浏览器额外带 `X-Frame-Options: DENY` 与 `frame-ancestors 'none'` 防点击劫持（钉钉客户端例外，见「钉钉工作台」一节）；同一「出口 IP + 班级 + 学生 ID」连续 3 次验证失败锁 15 分钟并告警，当次响应即返回锁定信息——按**匹配到的学生 ID** 而非输入姓名计数，避免交替使用中文名 / 大写拼音绕过次数限制，也避免校园 NAT / 反向代理下共用出口 IP 导致一人填错锁住所有人；提交后学生不可自行修改，变更须经教务纠错工单。写盘采用临时文件 + 原子 rename，单个请求异常返回明确错误而不使进程退出。

### 可选的第二验证因子与个人信息告知

教务后台「安全与合规设置」可对当前考试季开启：

- **第二验证因子 `sid4`**：出生日期 **+ 学号后四位** 同时正确才通过；学号数字不足 4 位自动左补零（`S001 → 0001`）。
- **个人信息处理告知**：学生验证前必须勾选同意；未同意时服务端连姓名匹配都不做，同意 / 拒绝动作均留痕，告知文本可由教务按学校规定修改。

> 遗留风险：出生日期是 8 位数字的弱凭据，双因子能显著提高冒用门槛，但仍不属于强身份认证（学号后四位可能在同学间流传）。如需更高强度，建议由教务线下核发一次性验证码或接入校园统一身份认证。

### 加密备份与恢复

教务后台「数据备份与恢复」可把整个考试季导出为 `EXAMBAK1:` 密文文件：密钥由**教务输入的备份口令**经 scrypt 派生，不依赖 `data/.key`，因此换机器、换密钥、容器重建后仍可恢复。恢复前校验格式 / 口令 / GCM 认证标签 / SHA-256 校验和 / 考试季结构，任一失败都不写盘。备份口令不落盘、不写日志，**忘记口令即无法恢复**，请按学校规定单独保管。

## 输入时间与终端设备记录

学生每次验证、提交、重填、越权写入被拒，服务端都按**服务器时钟**记一条时间线，并从 User-Agent 解析设备类型 / 品牌 / 型号 / 系统 / 浏览器 / 内嵌 App（微信、企业微信、QQ浏览器、钉钉工作台及其版本）；客户端补充上报的屏幕、UA-CH 高熵值（`getHighEntropyValues` 的机型、平台版本、架构、位数、完整版本列表）单独存放并明确标注「可伪造」。教务后台可直接查看并导出 `…-输入时间与设备.csv`。

| 终端 | 识别精度 |
|---|---|
| Android | 通常可到具体机型（小米 Mi 10、华为 P40 Pro、三星 SM-S918B） |
| iPhone / iPad | 仅到设备系列 + iOS 版本，Apple UA 不含具体机型 |
| Windows / macOS | 仅操作系统 + 浏览器，无 PC 型号 |

导出 CSV 另含「参考来源IP(可伪造)」列：反向代理下所有请求的 TCP 对端可能统一显示为网关地址（线上实测为 `127.0.0.1`），该列单独记录转发头供参考，**不参与锁定或鉴权判定**。完整字段说明与限制见 `src/使用与部署说明.md` 第八、九节。

## 钉钉工作台（H5 微应用）

把线上地址配置为企业内部 H5 微应用的「移动端首页地址」和「PC 端首页地址」，再创建并发布版本，即可在钉钉工作台里打开同一套完整后端，无需另做一套前端。

- **PC 端是 iframe 打开的**：`X-Frame-Options: DENY` 或 `frame-ancestors 'none'` 会让 PC 工作台显示空白页。服务端因此按请求 UA 判断：只有钉钉客户端（`DingTalk` / `AliApp(DingTalk/...)` / `com.laiwang.DingTalk`）请求才省略 DENY 并把 CSP 放宽为 `frame-ancestors *`；普通浏览器、微信等仍保持禁止嵌套，避免点击劫持。
- 若某些定制客户端的 UA 无法识别，可显式设置环境变量 `EXAM_FRAME_ANY=1` 放宽所有来源；**仅在受控内网使用**，且会失去点击劫持防护。
- **WorkBuddy 云端网关会剥离 `X-Frame-Options` 并在 `frame-ancestors` 追加 `*`**，这一点不受本仓库代码控制：云端实例天然允许被任意站点 iframe 嵌套，请勿把公网实例当作正式报考环境。自建服务 / 校内服务器不受此影响，按上一条的 UA 策略生效。
- 钉钉内置浏览器的 UA 会被设备时间线识别为「钉钉 x.y.z」，与设备型号同时留痕；教务后台导出 CSV 时可直接按渠道区分提交来源。
- 应用可见范围应按「仅教务小范围」设置，不要设为全员可见；测试环境尤其不要向全体师生开放。

## 回归验证

```bash
cd src
# 建议先用空的 data/ 目录另起一个端口启动，脚本会改口令、窗口并写入测试记录
PORT=8093 node server.js
python tools/verify.py                       # 默认验证 http://127.0.0.1:8093
# VERIFY_URL=http://127.0.0.1:8094 python tools/verify.py
```

`tools/verify.py` 零第三方依赖，覆盖 77 项断言：零名单启动 / 密文落盘 / 原子写入 / 静态穿越 / 身份验证与信息泄露 / 双因子 / 告知同意与留痕 / 服务端权威时间与设备识别（含钉钉渠道）/ 心跳去重 / 窗口关闭越权 / 后台鉴权与改口令 / 加密备份恢复（错口令、篡改、错校验和、弱口令）/ 失败锁定按学生隔离 / 中文名与大写拼音交替不能绕过失败锁定 / 前端 ticket 不放行 / 前端零虚构名单与服务不可达只读阻断 / 钉钉工作台 iframe 兼容（钉钉 UA 放宽、普通浏览器与微信 UA 仍 DENY）/ 教务可修改档案来源说明与纸质签署说明。脚本只使用公开默认口令与随机生成的测试口令，不含任何真实凭据或真实学生数据。

另有换环境恢复、异常兜底、真实浏览器渲染等独立验证，及线上各轮复测，明细见《上线测试指引》第七节。

## 合规提醒

姓名、性别、出生日期、设备型号、IP、输入时间戳都属于个人信息。上公有云或公网托管前请先确认学校是否允许，并按学校规定告知学生、留存依据；不允许上云时用校内局域网常开电脑即可。正式对外服务请配置 HTTPS。仓库中的 14 名学生均为虚构示例数据，不含任何真实学生信息。
